# 0.3.1-alpha: автоматическая очистка и диагностика

TTL включён по умолчанию, 86400 секунд от сохранения полного файла.
NSFileCreationDate выставляется при помещении в кеш; NSFileModificationDate
обновляется при чтении только для LRU и не продлевает TTL. Для файлов 0.3.0
используется уже существующая дата создания, при отсутствии — modification date.

Проверки всего каталога: запуск controller, возврат в foreground, периодически
раз в 60 секунд tick, чтение/добавление/подсчёт кеша и освобождение активного файла.
Очистка затрагивает только регулярные MP3 в собственном DNVOT-Audio. Активный файл
защищён до stop/replacement; логи и настройки не удаляются. Удаления/ошибки
фиксируются как cache_cleanup. При suspend/завершении процесса таймер не работает:
очистка выполняется при следующем запуске/возврате, без обещаний точного фонового
срабатывания через 24 часа. Лимит объёма 128 МБ сохраняется.

Убрано хранение сетевых URL перевода в NSCache: после истечения файлового TTL
нужен свежий запрос к API, а не повторное использование старой подписанной ссылки.
Полные готовые файлы по-прежнему кешируются и переиспользуются до истечения TTL.
Исправлены per-video counters/last attempt, маркировка cancelled и контекст trace.
Синхронизация/прокси/исключения языков не менялись.

## Проверено

ARM64 -Werror, ld64 fatal warnings, Mach-O/UUID/constructor/ad-hoc signatures.
UBSan: TTL до/на/после 24ч, чтение не продлевает срок, LRU не заменяет creation,
missing dates/fallback, rollback часов, active protection/release. Прежние
language/proxy/sync/protobuf и Google Protobuf parity прошли.

## Ограничение

Тесты TTL исполняют политику с контролируемым временем, не ждут реальные сутки
и не исполняют Foundation на iPhone. iOS filesystem/timer/active-file cleanup
0.3.1 требует проверки на устройстве. Успехи автоматики/экспорта относятся к
пользовательскому журналу 0.3.0. API Foundation: creationDate и setAttributes
сверены с официальной документацией Apple.
