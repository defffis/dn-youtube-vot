# Анализ и принятые решения

## Что находилось в IPA

Приложение: `com.google.ios.youtube`, версия 21.40.5, минимальная iOS 16.0.
Основной исполняемый файл — ARM64 Mach-O с `cryptid=0`, то есть предоставленный
бинарник уже доступен для статического анализа. Инструменты проекта не
содержат средств расшифровки приложений.

В Frameworks присутствовали CydiaSubstrate, YTLite, YouTubeDislikesReturn,
DontEatMyContent, YTUHD, YTVideoOverlay, YTABConfig, YouPiP, YouGroupSettings,
NoYTPremium, sideloadKeychainFix и libundirect. Также присутствовал штатный
widevine_cdm_secured_ios.framework.

У изученных YTVideoOverlay и YTLite обнаружена ссылка на `MSHookMessageEx`.
Новая реализация её не использует. Перехваты установлены собственным кодом
через `class_addMethod` / `class_replaceMethod` и `imp_implementationWithBlock`.
Предыдущая реализация сохраняется и вызывается, включая вариант, когда ранее
её уже изменил другой патч.

## Адаптер плеера

Основная точка входа — `YTPlayerViewController` из самого YouTube.

| Задача | Найденный интерфейс |
|---|---|
| ID основного ролика | `contentVideoID`, резервно `currentVideoID` |
| Позиция | `contentVideoMediaTime`, резервно `currentVideoMediaTime` |
| Длительность | `currentVideoTotalMediaTime` |
| Активный контроллер | `activeVideo` |
| Скорость | `activePlaybackRateModel.activeRate` |
| Громкость | `volume`, `setVolume:` |
| Реклама | `isPlayingAd`, `isPlayingAdSurvey`, `isPlayingAdIntro` |
| Аудиоформат | `activeVideo.selectedAudioFormat` |
| Аудиопоток | `MLFormat.URL`, `itag`, `DRMFamily` |
| Внешнее воспроизведение | `activeVideo.isExternalPlaybackActive` |

`tools/inspect_objc.py` использован для чтения Objective-C метаданных с учётом
формата chained pointers в данном Mach-O. Требуемые селекторы и сигнатуры
подтверждены статически. Нет жёстких адресов функций и смещений кода.

Состояния числовых перечислений нативного плеера не приравниваются к состояниям
YouTube IFrame API: это разные интерфейсы. Для определения воспроизведения
используются события play/pause, `attemptingToPlay` и движение медиавремени.

## Протокол перевода

Протокол перенесён из актуальной открытой реализации vot.js в небольшой
собственный код Objective-C++/C++. Нет браузерного движка, скрытого WebView,
DOM, Tampermonkey, Node.js или JavaScriptCore внутри приложения.

1. Сессия: `POST /session/create`, protobuf, модуль `video-translation`.
2. Запрос: `POST /video-translation/translate`, ID YouTube в публичной ссылке,
   длительность, языки, optional video_file_url.
3. Подписи: HMAC-SHA256 по схеме Vtrans, одноразовый UUID и секрет сессии.
4. Ожидание: ограниченный опрос; ответы старого ролика отбрасываются по поколению.
5. При запросе аудио: чтение доступного незащищённого потока из плеера, загрузка
   не более 32 МБ и `PUT /video-translation/audio`.
6. Если поток недоступен: уведомление `/video-translation/fail-audio-js` и
   резервный запрос с пустым audioInfo, аналогичный предусмотренному vot.js
   сценарию ошибки получения аудио. Успех серверного получения не гарантирован.
7. Готовая HTTPS-дорожка воспроизводится отдельным AVPlayer.

Компонент сервиса в этой версии: `26.10.0.1796`. Он зафиксирован вместе с
протоколом. Изменение внешнего API может потребовать обновления клиента.

## Синхронизация

Проверка состояния выполняется каждые 200 мс в основном run loop. При готовой
дорожке сравниваются медиавремя YouTube и время AVPlayer с учётом смещения.
До 70 мс коррекция не применяется, от 70 до 350 мс используется небольшое
изменение скорости, свыше 350 мс выполняется seek. Спектральный алгоритм
AVPlayerItem выбран для изменения скорости с сохранением высоты голоса.

При рекламе, паузе, остановке времени, ошибке, переключении видео или внешнем
воспроизведении аудио приостанавливается, а громкость оригинала восстанавливается.
Изменение пользователем исходной громкости учитывается в сохранённом уровне.

Точность и поведение при сетевых задержках не измерены на iPhone. Порог 350 мс
является параметром политики, а не утверждением о достигнутой точности.

## Подтверждённые проверки и границы

- Сборка Objective-C++/C++17/ARC/blocks без предупреждений компилятора и линковщика.
- Mach-O ARM64/iOS, install name, только системные зависимости.
- Все SHA-256 хеши страниц ad-hoc-подписи совпадают.
- Нативные запросы совпадают с Google Protobuf по байтам для сессии и перевода.
- Протокол проверен на повреждённых varint, усечённых строках и фиксированных
  полях; бинарное аудио не трактуется как текст.
- Политика синхронизации проверена для паузы, seek, рекламы, буферизации,
  изменения скорости, смещения и выхода за предел частичной дорожки.
- Внедрение в копию IPA проверено по сохранению прежних зависимостей,
  неизменности Info.plist, наличию нового load command и ZIP CRC.
- Результаты реальных запросов сохранены отдельно; даже успешный HTTP не
  означает готовый перевод. Поле `translated_audio_received` отражает именно
  факт получения URL дорожки в соответствующем тесте.

Не проверены запуск UIKit, кнопка в реальном плеере, реальное проигрывание,
долговременная синхронизация, фон, PiP и работа на чистой IPA. Эти пункты нельзя
выдать за успешно завершённые по результатам компиляции.

## Живые результаты 25.10.2026

Контрольный прямой MP4 из тестовых данных vot.js: статус перевода 1,
получен HTTPS URL дорожки, Range-запрос вернул HTTP 206 и 1024 байта
`audio/mpeg`. Сам URL дорожки и секрет сессии в отчёт не сохранялись.

Тесты публичных ссылок YouTube: сервис запросил исходное аудио (6), принял
резервные вызовы fail-audio-js и audio (HTTP 200), вернул ожидание (2),
затем ошибку (0). Это сохраняется как незавершённая проверка получения
перевода YouTube. Загрузка реального исходного аудиопотока из нативного
плеера и его полный upload требуют запуска на устройстве.

При повторных запросах сохранён параметр firstRequest=true, как в текущем
vot.js. В живом тесте вариант с false приводил к HTTP 400. Это отличие
наблюдаемого API от комментария в схеме учтено в клиенте.
