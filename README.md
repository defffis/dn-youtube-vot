# DN YouTube Voice Translation

**Текущий выпуск: 0.1.0-alpha · экспериментальная версия**

[Фактический статус](STATUS.md) · [План задач](ROADMAP.md) · [История изменений](CHANGELOG.md) · [Релизы](https://github.com/defffis/dn-youtube-vot/releases)

Исходники хранятся в этом закрытом репозитории. Готовые `.dylib`, тестовая IPA
и исходный архив первого выпуска доступны в Releases. Бинарники и IPA
не включаются в историю Git.

Независимый нативный патч для озвучки видео в YouTube через протокол Yandex VOT.
Собран 25 октября 2026 года в Linux. Архитектура ARM64, минимальная iOS 16.0.

**Это экспериментальная сборка. Она не запускалась на iPhone.** Сборка, двоичный
формат, контрольные суммы подписи, кодирование запросов, основная логика
синхронизации и внедрение в предоставленный IPA проверены отдельно. Эти проверки
не заменяют запуск на устройстве и проверку реального перевода в приложении.
В контрольном запросе для доступного напрямую MP4 получен готовый перевод и
проверена доступность MP3 (`docs/verification/2026-10-25/service-smoke-control.json`). Тесты ссылок
YouTube завершались ошибкой сервиса (`docs/verification/2026-10-25/service-smoke-speech.json`).
Успешный перевод через плеер YouTube на iPhone ещё не подтверждён.

## Что реализовано в коде

- Собственная кнопка «Перевод» в области плеера и нативная панель настроек.
- Определение текущего ролика и запрос озвучки на русский, английский или казахский.
- Автоопределение исходного языка или ручной выбор одного из указанных в панели.
- Отдельная громкость оригинала и перевода; приглушение оригинала во время
  фактического воспроизведения озвучки и восстановление его громкости при остановке.
- Отслеживание времени и скорости видео, пауз, перемотки, рекламы и смены ролика.
- Коррекция малого рассогласования скоростью в пределах 3%; перемотка аудио при
  отклонении более 350 мс; ручное смещение в пределах ±5 секунд.
- Отмена сетевых запросов и защита от запоздавшего результата предыдущего видео.
- Поддержка частичной озвучки с продолжением опроса сервиса.
- Получение доступного аудиопотока из плеера и передача его сервису при запросе
  исходного аудио. Лимит файла — 32 МБ; это ограничение данной первой версии.
- Резервный запрос самостоятельного получения аудио сервисом, по схеме vot.js.
- Необязательный автоперевод следующих видео и копирование диагностики.

Ссылка и, при необходимости, исходное аудио ролика передаются Яндексу. Это явно
указано в панели перед кнопкой включения. Отдельный сервер пользователя, Mac,
API-ключ или GitHub Actions для этой реализации не требуются.

## Независимость от модов из примера

Патч не импортирует YTLite, Substrate, YouPiP, YTVideoOverlay и другие добавленные
библиотеки. Для перехвата методов используются Objective-C runtime и собственные
блоки. Вызывается сохранённая предыдущая реализация метода, чтобы сохранялась
цепочка перехватов, если в приложении уже есть другой мод.

Код обращается к внутренним классам самого YouTube. Требуемые методы обнаружены
в основном исполняемом файле YouTube 21.40.5, а не в сторонних патчах.
Соответствие селекторов и сигнатур записано в `docs/verification/2026-10-25/youtube-compatibility.json`.

Независимость по ссылкам и API проверена статически. Совместимость с чистым
YouTube, с отдельными сочетаниями модов и с другими версиями требует проверки
на устройстве. При изменении приватных методов YouTube адаптер может потребовать
обновления. Перед установкой каждого перехвата проверяется его сигнатура.

## Файлы

- `build/DNYouTubeVOT.dylib` — готовая библиотека с ad-hoc-подписью.
- `src/` — собственный Objective-C++ код, протокол и политика синхронизации.
- `docs/verification/2026-10-25/` — зафиксированные результаты проверок первого выпуска.
- `tools/patch_ipa.py` — добавление библиотеки в отдельную копию IPA.
- `tools/setup_toolchain.py`, `tools/toolchain-lock.json` — восстановление
  фиксированной среды сборки с проверкой скачанных пакетов.
- `docs/ANALYSIS.md` — устройство реализации, источники и ограничения.
- `docs/DEVICE_TEST.md` — последовательность проверки на iPhone.

## Установка готовой тестовой IPA

В отдельной тестовой IPA библиотека уже добавлена и включена в команды загрузки
основного исполняемого файла. Остальные моды из присланной IPA сохранены.
Исходный пользовательский файл не изменяется.

**Тестовая IPA не подписана для установки на обычный iPhone.** Её необходимо
переподписать вместе со встроенными библиотеками своим способом установки.
Используйте файл только если можете установить переподписанный IPA.

После установки откройте обычное видео. В области плеера ожидается кнопка
«Перевод». Нажмите её, выберите целевой язык и «Включить перевод».
На первом запуске используйте короткое разговорное видео на английском.
Автоперевод по умолчанию выключен.

## Самостоятельное добавление dylib в другую IPA

Можно внедрить `DNYouTubeVOT.dylib` через используемый инструмент подписи,
который поддерживает добавление динамических библиотек. Необходимо изменить
команды загрузки исполняемого файла; простого копирования файла недостаточно.

Для Linux предоставлен отдельный скрипт:

```bash
python3 tools/patch_ipa.py source.ipa build/DNYouTubeVOT.dylib YouTube-DNVOT.ipa
```

Он принимает только уже расшифрованный thin ARM64 Mach-O и не выполняет
расшифровку или подпись. Он сохраняет прежние зависимости приложения, добавляет
`@rpath/DNYouTubeVOT.dylib`, снимает прежнюю подпись основного бинарника,
проверяет ZIP и записывает отчёт. Входной файл не перезаписывается.
Если места в заголовке Mach-O недостаточно, скрипт прекращает работу.

## Ручная сборка в GitHub Actions

Вкладка Actions → Manual Linux build and checks → Run workflow. Запуск только
вручную, расписания и автоматического запуска при push нет. Workflow собирает
библиотеку в Linux, выполняет тесты и сохраняет артефакт; он не подписывает IPA
и не проверяет приложение на iPhone. Его выполнение в GitHub пока не подтверждено.

## Сборка и тесты в Linux

В текущей среде инструменты находятся в `/opt/ios-toolchain`:

```bash
bash build.sh
bash test.sh
```

Для независимой проверки protobuf нужен Python-пакет `protobuf==6.33.0`.
Для тестов нужен системный g++ с UBSan. Сами dylib компилируются Clang 18.1.3
и линкуются ld64.lld. Пакет SDK называется iPhoneOS16.5.sdk, однако его
SDKSettings.json обозначает 16.4; в Mach-O записано значение 16.4.

Восстановить инструменты на Ubuntu 24.04 x86_64:

```bash
python3 tools/setup_toolchain.py
bash build.sh
```

При отсутствии доступа к `/opt` можно выбрать каталог:

```bash
export IOS_TOOLCHAIN_ROOT="$PWD/toolchain"
python3 tools/setup_toolchain.py
bash build.sh
```

В архив не включены SDK и компилятор. Восстановление требует доступа к интернету.
Загрузки проверяются по зафиксированным SHA-256/SHA-512.

Живой тест сервиса запускается отдельно и отправляет публичную ссылку Яндексу:

```bash
python3 tools/smoke_service.py --video VIDEO_ID --duration SECONDS --fallback --wait 300
```

Он использует кодировщик запросов из `src/VOTWire.hpp`, собранный в
`build/core_tests`. Он не запускает iOS dylib и не проверяет UIKit.

## Ограничения первой версии

- Используется стандартная озвучка VOT. Режим «живых голосов», требующий аккаунт,
  не реализован. Сообщение о необходимости входа показывается пользователю.
- Нет гарантии качества и доступности внешнего сервиса на каждом видео.
- Нет гарантии перевода новых роликов, для которых недоступен исходный поток;
  резервное серверное получение аудио может завершиться ошибкой.
- Не поддерживаются прямые эфиры и видео длиннее четырёх часов.
- Shorts, Cast/AirPlay, фон и PiP не прошли проверку. При определённом внешнем
  воспроизведении озвучка приостанавливается; патч не добавляет фоновое
  воспроизведение или PiP в исходное приложение.
- Паузы отслеживаются перехватами и движением времени; при буферизации возможна
  задержка остановки озвучки до примерно 0.4 секунды. Реальное поведение требует
  замера на устройстве.
- Настоящий интерфейс, плавность звука и конфликт с конкретными модами нужно
  проверить на iPhone. Диагностика не содержит секрет сессии или URL аудио.
